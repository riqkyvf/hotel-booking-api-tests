# Автотесты Hotel Booking API

[![API tests](https://github.com/riqkyvf/hotel-booking-api-tests/actions/workflows/api-tests.yml/badge.svg?branch=main)](https://github.com/riqkyvf/hotel-booking-api-tests/actions/workflows/api-tests.yml)

Автотесты для [Hotel Booking API](https://github.com/riqkyvf/hotel-booking-api) на **Python, pytest и requests**. Набор проверяет 29 операций: регистрацию и права доступа, отели и номера, доступность, бронирования, платежи и health. Сценарии охватывают конкуренцию, повторы с `Idempotency-Key` и переходы состояний с проверкой в PostgreSQL.

[Запуски CI и артефакты Allure](https://github.com/riqkyvf/hotel-booking-api-tests/actions/workflows/api-tests.yml) · [Карта покрытия](docs/README.md#карта-покрытия-api) · [Состав smoke](docs/README.md#smoke-suite)

## Подход к тестированию

- HTTP-запросы вынесены в `api/`, проверки результата остаются в тестах, чтобы сценарий читался последовательно.
- Тесты создают собственных пользователей, отели и номера, чтобы уменьшить зависимость от исходных данных стенда. Однотипные проверки границ и валидации параметризованы.
- После изменения проверяется сохранённое состояние, после отказа — отсутствие нежелательных изменений.
- SQL используется для подготовки дат без длительного ожидания и проверки записей и истории состояний. Переходы состояний выполняет приложение.
- Smoke охватывает основной путь и ключевые отказы; полный набор добавляет границы, права, состояния и конкурентные запросы.

Примеры проверок: [основной путь бронирования](tests/bookings/test_booking_flow.py), [сохранность профиля при отказе](tests/users/test_profile.py), [конкурентное бронирование](tests/bookings/test_booking_concurrency.py).

При локальном запуске созданные данные остаются в БД: общей очистки после тестов нет. В CI временный стенд и его данные удаляются после прогона. Локальные проверки последнего администратора используют отдельный временный стенд, который удаляется скриптом.

## Быстрый старт

Нужны Git, Python и запущенный Docker Desktop в режиме Linux containers. В CI используется Python 3.14.2; команды ниже рассчитаны на эту же версию и PowerShell.

1. Поднимите локальный API с PostgreSQL через Docker Compose и дождитесь `GET /api/v1/health/ready`. [Запуск стенда](docs/README.md#запуск-отдельного-приложения)
2. В другом окне PowerShell клонируйте автотесты и перейдите в их каталог. Если репозиторий уже есть, сразу перейдите в него.

```powershell
git clone https://github.com/riqkyvf/hotel-booking-api-tests.git
Set-Location hotel-booking-api-tests
```

3. Выполните команды ниже. Они установят зависимости, создадут локальный `.env` из шаблона [`.env.example`](.env.example) и запустят 14 smoke-проверок. Готовый `.env` хранится только на вашей машине. Если файл уже есть, команда сохранит ваши настройки.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m pytest -m smoke -q
```

Значения шаблона подходят для стандартного Compose-стенда приложения. Если вы меняли адреса или учётные данные стенда, укажите их в `.env`.

| Переменная | Для чего нужна |
| --- | --- |
| `API_BASE_URL` | Адрес API. По умолчанию `http://localhost:8000/api/v1` |
| `API_ADMIN_EMAIL`, `API_ADMIN_PASSWORD` | Активный администратор для подготовки отелей и номеров |
| `TEST_DATABASE_URL` | Строка подключения к той же базе PostgreSQL, которую использует API. Нужна для тестов с меткой `db` |

Для полного локального прогона на тестовом стенде выполните обе команды.

```powershell
.\.venv\Scripts\python.exe -m pytest -m 'not isolated_admin' -q --tb=short --durations=15 --junitxml=junit-full.xml
.\.venv\Scripts\python.exe scripts/run_last_admin_tests.py
```

Вторая команда создаёт временный локальный стенд. [Условия запуска](docs/testing-auth.md#отдельный-запуск-защиты-последнего-admin)

## GitHub Actions и Allure

[API tests](.github/workflows/api-tests.yml) запускает smoke на pull request в `main` и при каждом `push` в `main`. Для ручного запуска откройте **Actions → API tests → Run workflow** и выберите `smoke` или `full`. Режим `full` включает DB-тесты и отдельную финальную фазу из трёх проверок защиты последнего администратора.

CI поднимает временный стенд с версией приложения из шага **Check out API**. Учётные данные генерируются при запуске.

На вкладке **Summary** видны результаты, время каждой фазы, версии API и тестов и ссылка на артефакт. Скачайте архив запуска и откройте `allure-report/index.html`. В режиме `full` Allure объединяет обе фазы. Для диагностики в архиве также есть JUnit и логи Compose.

[Генерация Allure-отчёта локально](docs/README.md#локальный-отчёт-allure)

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `tests/` | Сценарии по функциональным областям, фикстуры и общая проверка ошибок |
| `api/` | Функции HTTP-запросов на requests |
| `data/`, `schemas/` | Наборы параметров и JSON Schema ответов |
| `db.py` | SQL-подготовка дат и чтение истории состояний |
| `scripts/` | Запуск проверок последнего администратора и формирование сводки CI |
| `docs/` | Карта покрытия, сценарии и пояснения к проверкам |

```text
tests/
├── auth/          # Регистрация, вход, JWT и административные права
├── users/         # Профиль, управление пользователями, последний admin
├── hotels/        # Каталог отелей, цены и управление отелями
├── rooms/         # Номера, доступность и ограничения при действующей брони
├── bookings/      # Бронирования, доступ, состояния и идемпотентность
├── payments/      # Отказы оплаты, повторы и конкурентные платежи
├── conftest.py    # Общие фикстуры: адрес API, пользователи, токены и брони
├── assertions.py  # Общая проверка контракта ошибок
└── test_health.py # Проверки live и ready
```

Общие фикстуры из `tests/conftest.py` доступны всем вложенным папкам. Фикстуры одного модуля остаются рядом с его тестами. Сценарии на стыке областей находятся в папке основного проверяемого правила: например, отмена с возвратом платежа — в `bookings/`.

Чтобы запустить одну область, передайте её путь, например:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/bookings/ -q
```
