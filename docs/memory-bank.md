## Версия приложения и ожидаемое поведение

Приложение `hotel-booking-api` находится в отдельном репозитории. В текущем workflow тестов шаг `Check out API` закреплён на коммите `0d8396f38c8a7b727648585e33b3d34fe54652ab`. Ссылки на требования и REST-спецификацию в документации ведут в `main` приложения, поэтому могут описывать более позднюю версию. При расхождении ожиданий с результатом существенна версия именно проверяемого приложения; наличие ссылки на `main` не доказывает дефект закреплённой версии.

Источники: [workflow, шаг Check out API](../.github/workflows/api-tests.yml), [контракт и ссылки на первоисточники](README.md#контракт). Коммит применим к текущему workflow; при его изменении запись требует сверки.

## Изоляция проверок последнего активного администратора

Подготовка этих проверок понижает роли остальных активных администраторов, чтобы оставить одного. Это причина отдельного запуска: локальный runner создаёт временные API и PostgreSQL и запрашивает удаление своих контейнеров и сети в `finally`. Он использует уже собранный образ `hotel-booking-api`; обычный локальный стенд для этой подготовки не предназначен.

В режиме `--reuse-ci-stand` runner использует одноразовый стенд финальной фазы `full`. Код проверяет GitHub-hosted окружение, режим `full` и loopback URL. Этот режим не является способом запуска на произвольном существующем стенде. Основная фаза `full` исключает маркер `isolated_admin`; успешная основная фаза сама по себе не означает выполнение проверок последнего администратора.

Источники: [runner](../scripts/run_last_admin_tests.py), [workflow](../.github/workflows/api-tests.yml), [условия запуска](testing-auth.md#отдельный-запуск-защиты-последнего-admin), [проверки](../tests/users/test_last_admin.py). Применимо к текущей реализации runner и CI.

## Известное расхождение схемы профиля

В локальной документации зафиксировано, что OpenAPI допускает `null` для `email` и `name`, а API отклоняет такие значения; `null` используется для очистки телефона. Это документированная особенность, а не результат нового прогона. В записи документации не указан коммит приложения, к которому относится расхождение: при изменении ожиданий тестов профиля нужно сверить требования, OpenAPI и поведение целевой версии API.

Источники: [документация профиля](testing-auth.md#profile-checklist), [существующие проверки](../tests/users/test_profile.py), [ссылки на контракт](README.md#контракт).

## Формат подробного каталога проверок

Для пилотной области отмены бронирования согласовано дополнить тематический документ конкретными проверками: ID, приоритет, условия и действие, ожидаемый результат, источник, точный автотест с вариантами параметризации и состояние покрытия. Таблицы содержат пять колонок: ID, приоритет, проверка, ожидаемый результат, автотест и варианты. Источники указываются для группы, ограничения покрытия — отдельно; строки читаются самостоятельно. Общая легенда находится в [docs/README.md](README.md#check-catalog). Сложные сценарии описываются пошагово в том же документе, с существенными данными и результатами; детали реализации остаются в примечании. Это позволяет проследить покрытие без чтения всех фикстур и assertions; одну запись не нужно создавать для каждого `assert`.

Формат применён к [отмене](testing-bookings.md#cancellation-details), включая CAN-014 / CON-005, [истечению удержания](testing-bookings.md#booking-expiration-checklist) и [завершению проживания](testing-bookings.md#booking-completion). Приоритеты оценивают риск и не заменяют `smoke`; наличие автоматизации отделено от результата запуска. Остальные области пока обзорные. Источник решения — согласованный в чате подход к документации; требования сверены с коммитом API, указанным в каталогах. Пробелы покрытия перечислены там же, без дублирования в памяти.

В сценариях истечения и завершения работающий worker может выполнить переход раньше проверяемого запроса: конечный результат не доказывает, какой механизм его вызвал. Источники: [тест истечения](../tests/bookings/test_booking_expiration.py), [тесты завершения](../tests/bookings/test_booking_completion.py), FR-05 закреплённой в каталогах версии приложения.
