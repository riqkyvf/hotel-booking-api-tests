## Контракт API

Сведения ниже относятся к API версии `0d8396f`, закреплённой в [workflow](../.github/workflows/api-tests.yml). Источники ожиданий собраны в [карте рисков](product-risks.md#контракт-и-модель-продукта).

- **Ценовой поиск.** Диапазону должен соответствовать один включённый неархивный номер. При сортировке по цене используется минимум среди всех таких номеров отеля, независимо от диапазона. Спецификация версии `d70a50c7` формулирует правило явно. [Уточнение контракта](https://github.com/riqkyvf/hotel-booking-api/blob/d70a50c7dd6d3febe134010b5cb4a9c8cddb7089/docs/api-specification.md#отели) · [Проверка сортировки с фильтром](../tests/hotels/test_hotel_prices.py#L148)
- **Обновление профиля.** Допуск `null` для `name` и `email` в OpenAPI — подтверждённая ошибка документации. Контракт разрешает явный `null` только для `phone`. Для `name=null` и `email=null` тест проверяет `422 VALIDATION_ERROR` и сохранность профиля, а для `email=null` ещё и поле в деталях ошибки. [Контракт профиля](https://github.com/riqkyvf/hotel-booking-api/blob/0d8396f38c8a7b727648585e33b3d34fe54652ab/docs/api-specification.md#L89) · [Валидаторы ProfilePatch](https://github.com/riqkyvf/hotel-booking-api/blob/0d8396f38c8a7b727648585e33b3d34fe54652ab/app/schemas/__init__.py#L113) · [Проверка профиля](../tests/users/test_profile.py#L223)

## Ограничения проверок

- **Истечение JWT.** Срок хранится в подписанном поле `exp`. Проверка сравнивает ответы API на два токена одного пользователя с разным сроком, подписанные ключом тестового стенда. [Выпуск JWT](https://github.com/riqkyvf/hotel-booking-api/blob/0d8396f38c8a7b727648585e33b3d34fe54652ab/app/core/security.py#L24) · [Тест истечения](../tests/auth/test_token_expiration.py#L26)
- **Срок удержания брони.** Тест создания сверяет `expires_at` с окном HTTP-запроса плюс 30 минут и допуском ±5 секунд. Момент решения после ожидания блокировки остаётся за рамками этой проверки. В тесте истечения SQL-статусы читаются после `409` и до следующего GET. Статусы мог сохранить фоновый обработчик, поэтому результат отдельно не подтверждает сохранение изменений именно запросом оплаты. [Создание брони](../tests/bookings/test_booking_flow.py#L61) · [Истечение](../tests/bookings/test_booking_expiration.py#L14)
- **Последний активный администратор.** Покрыты три последовательных варианта изменения роли и активности. Одновременное изменение двух активных администраторов вне покрытия. [Изолированный тест](../tests/users/test_last_admin.py#L45)
